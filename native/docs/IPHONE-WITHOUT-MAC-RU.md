# Проверка iPhone без собственного Mac

Владелец сообщил 18 октября 2026, что Mac нет. Это не препятствует разработке: проект уже собирается и проверяется на облачном Mac в GitHub Actions. Симуляторная сборка не устанавливается на физический iPhone.

Для следующего этапа можно подготовить подписанную сборку на облачном Mac и передать её через TestFlight. Apple требует членство команды в Apple Developer Program для такой доставки. Сначала нужно выяснить, есть ли уже действующая команда владельца или доступ к университетской команде; покупать подписку заранее не требуется.

В старом `eas.json` уже указан App Store Connect app ID `6793826774`, а старый bundle ID — `com.olegkotikov.lifeplanner.alpha`. Это свидетельство прежней настройки доставки, но не подтверждение действующего членства или доступа. Нативный кандидат использует другой идентификатор; подменять старую запись или её сборку без отдельного решения не следует.

Членство проверено и активно. С отдельного разрешения владельца созданы Apple Distribution сертификат, профиль нового приложения и ключ API с ролью Developer. Семь параметров подписи и доставки сохранены в GitHub Secrets. Закрытые ключи не входят в исходники и обзорный ZIP.

## Подготовленная ручная сборка

В ветке подготовлен workflow `.github/workflows/native-iphone-archive.yml` и помощник `native/tools/archive_iphone.py`. Он собирает подписанный архив на облачном Mac и сохраняет IPA на семь дней. Ручной параметр загрузки по умолчанию выключен. Тег `ios-archive-*` запрашивает только экспорт, тег `testflight-*` — экспорт, проверку и загрузку в Apple. На pull request доставка не запускается. Профиль проверяется на точное соответствие идентификатору кандидата, команде, сроку действия и способу экспорта. Временный сертификат/профиль очищаются; ключи не входят в артефакт.

В GitHub Settings → Secrets and variables → Actions потребуются четыре repository secrets:

| Имя | Значение |
|---|---|
| `IOS_CERTIFICATE_BASE64` | Однострочный Base64 Apple Distribution сертификата с закрытым ключом в P12 |
| `IOS_CERTIFICATE_PASSWORD` | Пароль этого P12 |
| `IOS_PROFILE_BASE64` | Однострочный Base64 профиля для `com.olegkotikov.liveplanner.swift.dev` |
| `APPLE_TEAM_ID` | Идентификатор команды Apple Developer |

Для `app-store-connect` нужен App Store distribution profile; для `release-testing` — Ad Hoc profile с зарегистрированным iPhone. IPA первого типа нельзя просто открыть на телефоне: потребуется отдельная загрузка в App Store Connect и TestFlight. Экспорт Ad Hoc рассчитан только на устройства из профиля.

Не отправлять секреты в чат. Если сохранились материалы подписи Expo/EAS, сначала проверить их применимость: профиль старого bundle ID не подходит новому кандидату. Создание новых ключей и профилей можно организовать с Windows; собственный Mac для хранения исходников не требуется.

Помощники подписи и загрузки прошли проверку синтаксиса и отказа без секретов. Проверки приложения на Xcode 26.3 прошли, включая неподписанный Release-архив для iPhone. Подписанный экспорт запущен в run 39139994490; результат ещё проверяется. Для доставки нужны также `ASC_KEY_ID`, `ASC_ISSUER_ID`, `ASC_PRIVATE_KEY_BASE64`. Ручной запуск требует наличия workflow в основной ветке; явный тег позволяет проверить ветку миграции без её преждевременного слияния. Успех экспорта не означает успех загрузки и обработки Apple.

Порядок подготовки:

1. Завершить автоматические проверки текущего исходного кода.
2. Определить доступную команду Apple Developer и её разрешения. Не передавать пароль Apple ID, ключи и сертификаты в чат или репозиторий.
3. Создать согласованную запись приложения в App Store Connect, назначить идентификатор и настроить подпись через защищённые средства сборки. Нынешний идентификатор является идентификатором кандидата для разработки.
4. Подготовить и проверить архив для реального устройства, загрузить в App Store Connect и дождаться обработки. Создание учётной записи, принятие соглашений и платные действия выполняются владельцем.
5. Установить через TestFlight и пройти физическую приёмку из VALIDATION.md: перезапуск, резервная копия, даты, клавиатуры, доступность и доставка уведомлений.

Дополнительных покупок не было. Сборка в TestFlight пока не опубликована. Apple Developer показывает соглашение принятым 18 октября, однако App Store Connect после повторного входа продолжает блокировать создание записи приложения тем же соглашением. Текущее состояние отражено в TESTFLIGHT-UPLOAD-STATUS.md. Отсутствие установки не должно описываться как пройденная физическая приёмка.

Результат: run 39139994490 успешно создал и экспортировал подписанный IPA 0.1.0 (1). Файл скачан и проверен по SHA256 артефакта; загрузка в Apple намеренно не запускалась до создания записи приложения. Сначала необходимо устранить противоречивую блокировку соглашением в App Store Connect. Повторное принятие уже принятого соглашения не запрашивается.
